# AI 浏览器自动化测试 Agent MVP 方案

## 1. 总体方案

本项目交付一个供其他团队使用的 AI 测试 Agent 流水线。它以已有测试用例为输入，通过 Browser Agent 执行可见页面上的正流程测试，保存结论和证据，再把异常与无法判断的内容交给人工。

AI 用于提高人工测试效率，不替代人工最终验收。当前阶段优先验证可行性和正流程闭环，不追求完整测试平台。

## 2. MVP 边界

### 包含

- 读取已有、只读的测试用例；
- 默认尝试执行全部输入用例，不做前置能力分类；
- 使用 Cursor Agent 原生 Browser 操作和观察页面；
- 对每条用例记录状态、执行过程、原因和证据；
- 生成需要人工处理的用例清单；
- 首版以 Cursor Skill、模板和提示词交付。

### 不包含

- 独立的 Playwright 测试阶段；
- 读取或修改待测项目代码；
- 调用内部 API 或访问数据库；
- 自动修复测试发现的问题；
- 自动改写来源用例；
- 视觉体验、真实设备、CAPTCHA 等必须人工判断的能力；
- 多平台 Agent、常驻服务和完整测试管理 UI。

## 3. 执行流程

```text
测试人员提供运行配置和只读用例
  ↓
Browser Preflight
  ↓
主 Agent 顺序读取并调度每条用例
  ↓
/use-browser 观察页面、执行步骤、检查预期
  ↓
每条用例完成后立即更新状态并追加执行记录
  ↓
生成批次汇总和人工处理清单
```

用例假设彼此独立。MVP 可以复用相同账号的登录会话，但不得让前一条用例产生的业务数据成为后一条用例的隐式前置条件。

## 4. 判定规则

| 内部值 | 中文展示 | 含义 |
|---|---|---|
| `pending` | 待测试 | 尚未开始执行 |
| `passed` | 已通过 | 所有步骤执行完成，且每个预期都从可见页面直接观察到 |
| `failed` | 不通过 | 已观察到与预期相矛盾的页面行为 |
| `blocked` | 测试受阻 | 因 Browser、环境、登录、权限或前置数据而无法执行 |
| `inconclusive` | 无法判断 | 已执行，但可见页面不足以支持通过或不通过 |
| `retest_pending` | 待复测 | 修复或环境变化后等待重新执行 |

点击成功、页面没有报错或 Agent 走完步骤，都不能单独作为通过依据。`blocked` 和 `inconclusive` 不得转换为 `passed`。

默认把 `failed`、`blocked` 和 `inconclusive` 放入人工处理清单；测试人员可以在结果出来后增加人工测试范围。

## 5. 数据模型

MVP 保持三类表，不额外建立数据库实体：

| 数据 | 写入规则 | 最少内容 |
|---|---|---|
| 用例 `test_case` | 只读 | ID、标题、账号、前置条件、步骤、逐步预期 |
| 用例状态 `case_status` | 可更新 | run_id、用例 ID、Browser 状态、最后执行时间、最后记录 ID |
| 执行记录 `case_execution` | 只追加 | execution_id、run_id、用例 ID、尝试次数、起止时间、结论、步骤观察、原因、证据 |

批次的环境、Cursor 版本、开始时间和用例集版本可以保存在结果目录的 manifest/summary 中。若后期需要数据库查询，再将批次提升为独立实体。

## 6. 输入

### 测试用例

每条用例至少包含：

- 唯一 ID；
- 标题；
- 使用的账号标识；
- 前置条件；
- 有序步骤；
- 每一步的可观察预期。

### 运行配置

测试人员只提供必要信息：目标 URL、测试账号、禁止操作和必要备注。AI 在不改变业务语义的前提下自行处理滚动、等待、关闭无害提示和切换标签页等 UI 细节。

普通账号支持用户名/密码。短信 mock 账号使用“浏览器自动填入”标记：Agent 输入手机号并点击获取验证码，然后等待页面自动填写。

### 来源适配

首版支持 Markdown/结构化文本以跑通闭环。Excel 随后加入。飞书文档由外部飞书 Skill/CLI 完成下载和交互，本项目只消费其提供的本地结构化内容。

## 7. 证据与审计

每条执行记录至少包含：

- 实际执行步骤；
- 每一步观察到的页面结果；
- 最终 URL 或页面标题；
- 起止时间；
- 最终状态；
- 异常步骤和原因；
- 可用的截图引用。

状态表是当前快照，执行记录是历史事实。复测只能追加新记录，再更新状态表，不能修改旧记录。

## 8. 交付与演进

### MVP

- Cursor Agent 3.15.x Agent Window；
- Cursor 原生 `/use-browser`；
- Skill + 提示词 + 输入/结果模板；
- 文件形式的状态、记录和汇总。

### 后续

- Excel 适配；
- 多账号调度优化；
- 飞书适配；
- 其他 Browser Provider；
- 代码与数据库只读上下文；
- 独立 CLI/服务和插件 UI。

## 9. 当前进度与下一步

单次 Browser 登录验证和一次两用例闭环运行已经通过，状态、执行记录、汇总和截图均成功落盘，具体证据边界见 [Cursor Browser PoC 当前状态](poc-status.md)。下一步审计实际结果文件，并验证外部文件输入、中断恢复和复测追加记录，不扩大功能范围。
